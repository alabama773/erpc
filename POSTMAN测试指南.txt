================================================================
  Postman 测试指南 - Solana Gateway (sol-erpc)
================================================================

服务地址: http://localhost:4100
容器: solana-gateway (Docker, 后台运行)

先确认服务在跑:
  浏览器打开 http://localhost:4100/health
  看到 {"status":"ok","providers":[...3个...]} 就是正常


================================================================
  Postman 通用步骤 (每个请求都这样)
================================================================

1. 打开 Postman, 点 "+" 新建请求
2. 选方法 (POST 或 GET, 下面每个会标)
3. 地址栏贴 URL
4. 如果是 POST: 点 Body -> 选 raw -> 右边格式选 JSON -> 贴 body
5. 点 Send
6. 想看是哪个数据源服务的: 看返回的 Headers 标签 -> X-RPC-Provider

★ 规律:
  根地址 http://localhost:4100/  用 POST (要贴 body)
  带路径的 (/health /stats /block /address) 用 GET (不贴 body)

================================================================
  三、★核心: USDC 转账查询 (from/to/block/price/单位)
================================================================
   老板要的 from、to、block、price、单位 都在这两个接口里

--- 测试 6: 查某个区块的所有 USDC 转账 ---
方法: GET
地址: http://localhost:4100/block/435464598
预期: 返回该区块所有 USDC 转账, 每笔包含:
  from      转出方地址
  to        收款方地址
  amount    金额
  unit      单位 (USDC)
  price     实时美元价 (约 $1.00, 从 CoinGecko 拉)
  valueUsd  美元价值 = 金额 x 价格
  block     区块号
  signature 交易签名

只看涉及某地址的: 地址后加 ?address=某地址
  http://localhost:4100/block/435464598?address=6LY1JzAFVZsP2a2xKrtU6znQMQ5h4i7tocWdgrkZzkzF

--- 测试 7: 查某个钱包的 USDC 转账 (只给地址就能翻) ---
方法: GET
地址: http://localhost:4100/address/G9L3ac8qYKNy1gTxdmhxTbDVyGHf5NAaSDYzvkgitVLJ?limit=30
预期: 返回该钱包最近的 USDC 转账, 每笔包含:
  direction 方向 (in=收到 / out=转出)
  from      转出方
  to        收款方
  amount    金额
  unit      单位 (USDC)
  price     实时美元价
  valueUsd  美元价值
  block     区块号
  signature 交易签名

limit = 扫最近多少笔 (默认25, 最大200)
把地址换成任何你要查的钱包即可

================================================================
  返回的错误码怎么看 (修复后, 真实透传)
================================================================

网关现在会把数据源返回的真实 JSON-RPC 错误码原样传给你,
不再统一包成 "-32000 All providers exhausted"。看到 error 时
先对照下表判断是哪一类:

--- A. 数据可用性 (会自动换源, 全部没有才报错) ---
  -32001  Block ... cleaned up      该源把这个老块清掉了
  -32004  Block not available       这个 slot 没有区块
  -32007  slot skipped or missing   slot 被跳过
  -32009  slot ... in long-term storage
  行为: 网关会自动 failover 到还留着该块的源(如 helius)。
        只有当所有源都没有这个块时, 才把上面的错误返回给你。
        典型原因: 免费源只保留最近几天的块, 查太老的块要靠 helius。

--- B. 请求写错了 (立即返回, 不换源) ---
  -32602  Invalid params            参数个数/类型不对
  -32601  Method not found          方法名写错 / 该方法已废弃
  -32600  Invalid Request           请求结构不对(如缺 method)
  行为: 每个源都会同样报错, 所以立即返回, 改请求即可。

--- C. 全部源都挂了 (限流/网络) ---
  -32000  All providers exhausted ... 
  行为: 只有当所有源都被限流或网络失败时才会出现。
        等几秒重试, 或看 /stats 是不是都在 cooldown。

★ 判断技巧: 看返回头 X-RPC-Attempts。
  =1  一次就定了(B类确定性错误, 或直接成功)
  >1  换过源(A类可用性 failover, 或限流重试)


================================================================
  常见错误
================================================================

错误: "Use POST with a JSON-RPC body, or GET /health, GET /stats"
原因: 根地址 http://localhost:4100/ 用了 GET
解决: 改成 POST, Body 贴 JSON

错误: 连不上 / Could not send request
原因: 服务没开
解决: 打开 PowerShell, 执行:
      cd C:\Users\USER\erpc\solana
      docker compose up -d
      (等几秒再试)

错误: getBlockTime / getBlock 查老块返回 -32001 或 -32004
原因: 查的 slot 太老, 已被数据源清理(或本就不存在)
解决: 换一个较新的 slot; 确实要查很老的块需要 helius(付费源)
      保留更久。参考上面"返回的错误码怎么看" A 类说明。
